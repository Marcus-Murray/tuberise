# 7-Possible Solutions Thinking Rule

## Rule Activation

When the user requests systematic problem analysis or mentions "7-possible-solutions", "think about different approaches", or similar phrases, activate this rule.

## Rule Implementation

For any problem or task, systematically analyze 7 different approaches before implementing a solution. Follow this exact structure:

### 1. Problem Analysis
- Clearly define the problem or task at hand
- Identify constraints and requirements
- Understand the context and scope

### 2. Generate 7 Possible Solutions
For each solution, provide:
- **Approach Name**: Clear, descriptive title
- **Strategy**: How this approach would work
- **Pros**: Advantages and benefits
- **Cons**: Disadvantages and limitations
- **Implementation Complexity**: Low/Medium/High
- **Time Estimate**: Rough timeline for implementation

### 3. Solution Evaluation
Evaluate each solution against:
- **Feasibility**: Can it be implemented with current resources?
- **Effectiveness**: Will it solve the problem adequately?
- **Maintainability**: Is it sustainable long-term?
- **Risk Level**: What are the potential downsides?
- **Alignment**: Does it fit with project goals and standards?

### 4. Selection and Rationale
- **Chosen Solution**: Which approach was selected
- **Why This Solution**: Detailed rationale for the choice
- **Alternative Considerations**: Why other solutions were not chosen
- **Implementation Plan**: Next steps for the selected approach

## Required Output Format

Always provide:
1. Clear problem statement
2. 7 distinct solutions with full analysis
3. Evaluation matrix comparing approaches
4. Selected solution with detailed rationale
5. Implementation plan with next steps

## Quality Standards

- Each solution must be genuinely different, not just variations
- Consider both technical and business perspectives
- Include realistic time and complexity estimates
- Address potential failure modes and edge cases
- Align with project's technical standards and constraints
- Consider long-term maintainability and scalability

## Integration Points

- Use at the beginning of complex tasks
- Apply before major architectural decisions
- Include in code review processes for significant changes
- Document in project planning and design phases
- Reference in pull request descriptions for major features
